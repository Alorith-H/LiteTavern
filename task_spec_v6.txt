## 2. 自动继续（原版 Auto-continue）
- 设置 → 模型服务 → 生成参数区：「自动继续次数」步进 0–5，默认 2，
  副说明"回复达到长度上限时代写续接的次数，0 = 关闭"
- 触发：`max_tokens > 0` 且本次 completion tokens ≥ max_tokens×0.98
  → 自动复用「继续生成」管线追加（同一消息同一变体），计入次数，
  达到次数上限或用户点停止即停
- 追加期间照常：可滚动、可停止、token 累计、失败保留已生成部分

## 3. 聊天摘要（原版 Summarize）
- 设置 → 聊天组：「长对话自动摘要」Switch，**默认开**，副说明"对话太长时自动把早期内容
  压成摘要，保证不遗忘"
- 存储：会话 JSON 增加 `summary?: {text, updatedAt}`（不删原始消息，摘要只影响发送）
- 触发时机：**发送前**，开关开 且 消息总数 > 记忆长度(contextHistoryLimit)
  → 若 `summary` 为空或已过期（原始消息又新增了超出记忆长度的部分）
  → 调 API 用「超出记忆长度的早期消息」生成 **≤300 字中文摘要**
  - 期间 UI 显示进度态（输入栏上方细进度/文案"正在总结早期对话…"），可取消（取消=本次跳过摘要直接发）
  - 成功 → 存 summary → 继续发送
  - 失败/取消/超时(30s) → 本次**直接按现状发送**（只带最近记忆长度条），不阻塞聊天
- 发送组装：system 末尾追加 `【早期对话摘要】<text>`；历史仅带最近记忆长度条
- 聊天菜单：存在可总结历史时显示「立即总结早期对话」（手动触发同一管线，
  完成 snackbar「已总结」；无超长历史时隐藏）
- 摘要请求复用当前 API 配置与生成参数（temperature 可用 0.4）
