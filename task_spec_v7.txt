- 迁移：旧的 temperature/topP/maxTokens 字段 → 迁入「默认」预设后删除

## 3. 世界书高级字段编辑（引擎必须真实生效）
- 条目编辑弹窗在现有字段（keys/content/insertion_order/enabled）上**追加**：
  - `keysecondary`：逗号分隔输入，副说明"次要关键词——主词命中后，还需其中至少一个出现才注入"
  - `useProbability` Switch + `probability` 0–100 数字/slider，副说明"按概率随机注入"
  - `position` 三选（人话标签）：`对话开头注入`（0，进系统提示最前）/ `对话中按深度注入`（1）/
    `角色设定后注入`（2，系统提示里角色字段之后）
  - `depth` 0–99（仅 position=1 显示），副说明"插到倒数第 N 条消息之前"
  - `recursive` Switch，副说明"用已激活条目的内容继续匹配其它词条"
  - `scanDepth` 数字（0=全程），副说明"只回看最近 N 条消息找关键词"
- **引擎侧**（world_info_engine / prompt_builder）逐项核对，不生效的修：
  - position 0 vs 2 的**注入顺序区分**（0 在 system 最前，2 紧跟角色设定字段后）
  - position=1：激活条目以 **user 消息**形式插到历史倒数第 depth+1 条之前（depth=0 = 最新一条前）；
    渲染文本前缀 `[世界书] `，发送前的历史组装统一处理
  - keysecondary 的 AND 语义、probability 随机、recursive 3 层迭代、scanDepth 截断：
    逐条写**单元测试**（≥4 条）证明生效
- 旧条目缺字段 → 默认值兼容（secondary 空、probability 100、position 0、recursive false、scanDepth 50）

## 4. 角色卡导出（本批唯一允许的新依赖：share_plus）
- 角色编辑页右上 overflow 菜单新增「导出角色卡」→ 底部弹窗选格式：
  - **JSON**：按 chara_card_v2 规范重建（data 全字段 + 有内嵌世界书则带 character_book）
  - **PNG**：仅当该角色有原始 PNG 卡图（导入时存的图片字节仍在）——读原图字节，
    替换/新增 `tEXt chara` chunk 为新 JSON 的 base64（注意 zTXt 原文若存在则移除），
    CRC 正确计算；**没有原图的角色不显示 PNG 选项**
  - JSON 导入的角色只有 JSON 选项
- 落盘到 `getTemporaryDirectory()`，文件名 `<角色名>.json` / `<角色名>.png`
  （非法路径字符替换为 `_`）
- `share_plus` 的 `Share.shareXFiles([...])` 弹系统分享面板（微信/QQ/保存文件随意），
  取消则无动作；分享前后都要删临时文件的话用完即删（下次导出重新生成）
- pubspec 依赖只允许新增 share_plus 这一个；AndroidManifest 若需 query 权限按 share_plus
  官方 README 加（package visibility）
