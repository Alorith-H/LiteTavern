## 1. 世界书条目「按对话命中率」
- 语义：**每个对话**里，该角色卡词条被激活的比例 = `命中次数 / 该对话发送次数`
  （"发送" = 用户发一条消息触发的一次 prompt 组装；群聊轮转整轮只算 1 次）
- 统计存储：会话 JSON（单聊 `conversations/<charId>.json` / 群聊 group_ 同文件）新增
  `hitStats?: {<entryKey>: {hits: int}, _sends: int}`；
  entryKey 用条目稳定标识（有 id 用 id，否则 `keys首词|insertionOrder` 兜底，写清注释）
- 记录时机：prompt 组装完成（含摘要/不发的预览**不计**，只有真实 API 发送才 `_sends+1`；
  组装中激活的词条 `hits+1`）；随 saveConversation 持久化
- 展示两处：
  a) 世界书条目列表（编辑条目的那个列表页）每行副文本加 `本对话 3/12 · 25%`（无发送记录不显示）
  b) 聊天菜单「查看注入内容」底部加小节「本对话命中率」：已激活词条逐个 `名字 3/12 · 25%`，
     未命中过的词条不列
- 旧会话无 hitStats → 不显示，不迁移

## 2. 上下文占用查看 + 满了自动压缩
- **设置 → 生成参数区**新增「模型上下文窗口」数字输入（token，默认 `65536`，0 = 关闭占用%与自动压缩，
  副说明"模型单次能装下的最大 token，超了会自动压缩"）
- **聊天菜单**新增「上下文占用」（替代/并列现有"查看注入内容"——可合并进同一预览页，
  你判断交互，但必须一处能看到）显示：
  - 明细行：系统提示（角色卡+规则）≈X · 世界书 ≈Y · 摘要 ≈Z · 历史 N 条 ≈W → **合计 ≈T tokens**
  - 比例条（accent 填充）+ `T / 窗口 = P%`
  - token 估算公式：CJK 字符数×1.0 + 非 CJK 字符数/4（写成独立可测函数 `estimateTokens(String)`）
  - 若本次已有 API 返回的真实输入 token，追加显示「上次实际：202」
- **满压缩（自动，核心行为）**：
  - 发送前估算 > 窗口×90% → 自动压缩，**绝不允许发送失败或超窗硬拼**
  - 压缩策略（依次执行直到 ≤90%）：
    1. 历史条数减半（不低于 10 条）重算
    2. 仍超 → 走现有摘要管线：把「当前摘要+超记忆长度的更早历史」压成新摘要（复用 v0.6 摘要
       生成逻辑与 API 配置），存 summary 后按更短历史重发
    3. 摘要失败/超时 → 兜底：仅系统提示+世界书+最近 10 条发送，snackbar 告知"上下文已满，已裁剪发送"
  - 压缩生效时 snackbar 人话提示：「上下文占用过高，已自动压缩（P%）」
  - 自动压缩只在窗口>0 时启用；群聊同样生效
- 占用数据不持久化，实时计算即可

## 4. AI 角色卡创建器（对话式）
- **入口**：首页「导入」按钮改为菜单三选：`从文件导入` / `从链接下载` / `**AI 创建角色卡**`
  （FAB 若与导入联动，保持一致；图标 Icons.outlined 相应选用，禁止 emoji）
- **交互流程**（新建专门页面 `card_creator_screen.dart`，不是角色会话）：
  1. 顶部说明一句（人话）：「描述你想要的角色，或直接和 AI 聊，聊完点右下角生成」
  2. 对话区：系统提示 = 出题人/采访者（**不是扮演**）：让 AI 主动追问缺的信息
     （名字、性格、说话方式、场景、开场白），一次最多问 2 个问题，用户可一句话全答
  3. 流式输出、可停止、可继续——复用现有 ApiClient 与节流逻辑（能复用 chat 的就复用）
  4. 右下角固定主按钮「**生成角色卡**」：调 API 要求返回纯 JSON
     （name/description/personality/scenario/first_mes 六字段 + **character_book 内嵌世界书**，
     提示词里给字段说明；解析容错：围栏剥离、截断抢救）
  - **character_book 要求**（v0.8 追加）：AI 角色若有专有名词/地点/世界观规则，生成
    `character_book: {name: "<角色名>的世界书", entries: [{keys: [...], content, enabled: true,
    insertion_order, position: 0}]}`，条目 3–8 条、keys 为 1–4 个中英文关键词、content ≤200 字；
    没有可写的词条则返回 null（**不许编造凑数**）；条目字段与现有 WorldInfo/条目编辑模型对齐
  - 解析后 character_book 随卡入 character_edit_screen 预览（该页"卡内嵌世界书 · N 条"
    只读展示已支持，无需新做编辑），保存走现有入库（卡 JSON V2 自带 character_book）
  - 创建器对话里用户要求修改时（"世界书里把 X 改成 Y"）→ 重新点生成，整卡刷新
  5. 解析成功 → **打开现有 character_edit_screen 预览编辑**（传入内存卡，未保存态）→
     用户补头像/微调 → 走现有保存入库流程（不重复造保存逻辑）
  6. 解析失败 → snackbar + 保留对话，允许再点（可追加一句"把 JSON 再输出一遍"）
- 使用激活 API 配置与激活预设参数；页面样式符合编辑风（无卡片、行式输入）
- 创建器对话**不落库**（退出即弃，顶栏菜单给「清空对话」）
