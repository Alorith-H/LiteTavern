## 2. 流式输出中可自由滑动（用户报告的严重体验问题）
现象：**AI 输出过程中屏幕不能滑动，必须等输出结束**。要求修复：
a) 排查并移除生成期间任何触摸/滚动锁定（`NeverScrollableScrollPhysics`、`IgnorePointer`、`AbsorbPointer`、手势拦截等）——聊天列表任何时候都应可滚动
b) 自动跟随规则：只有当用户滚动位置在**底部 120px 以内**才自动跟到底；检测到用户已上滑离开底部 → 本段生成期间**不再强制回滚**；用户手动滚回底部后恢复跟随
c) 输出中滑动必须流畅（性能）：
   - 流式更新**按帧合并**：一帧内多个 token 只触发一次 setState（`SchedulerBinding.instance.addPostFrameCallback` 合并，或 ≥33ms 节流），禁止每个 token 全列表 rebuild
   - **缓存已完成消息的 widget**：非末条消息的气泡（含 markdown 渲染结果）构建后存入列表缓存，仅消息集变化时失效；流式期间只有最后一条 AI 气泡随数据更新
d) 生成中输入框保持可用（发送按钮变停止按钮即可，不要禁用整条输入栏）

## 3. 回复变体左右滑动切换（原版 swipe variants，标志性功能）
- 消息模型加 `variants: List<String>`（当前显示文本 + 变体历史；旧数据无此字段 → 空列表）
- **重新生成改为追加变体**：不再删除旧回复，生成结果 append 到 variants，当前视图切到新变体
- 最后一条 AI 消息支持**横向滑动**切换变体：手势判定 `|dx| > |dy|` 才响应横滑（否则让给竖向列表滚动）；只有 1 个变体时横滑无视觉响应
- 变体数 >1 时气泡底部显示小圆点指示器（可点按切换）
- 编辑消息 = 编辑当前显示的那个变体
- token 小字跟随当前变体；聊天统计把**所有变体**的消耗都计入累计（真实花销）
- 存储 JSON 带 variants，向后兼容

## 4. 继续生成（原版 Continue）
- 右上菜单"继续生成"：仅当最后一条是 AI 消息且未在生成时显示
- 实现：现有 messages 末尾附加指令（system 提示：「接着上一条回复的最后一个字继续输出，不要重复、不要重新开头」）发请求，**流式把结果追加到该条 AI 消息文本末尾**（同一条消息，不是新消息）
- token 统计、停止、滚动行为与普通生成一致
